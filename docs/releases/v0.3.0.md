# BTED v0.3.0 数据发布

v0.3.0 收录 **28,399 条转录本 3′ 端位置记录**，涉及 22 份来源数据和 13 篇论文。其中 `BATTER_S1_002` 只保留核查记录，没有端点。公开文件按 PMID 组织：每篇论文一个目录，保存该研究的 GFF3、可读元数据和完整来源信息；研究专属关系表也放在所属目录。记录内容和证据判断没有改变。论文与数据的对应关系见[来源说明](../SOURCES.md)。

## 发布目录

规范发布目录位于 [`data/public/v0.3.0/`](../../data/public/v0.3.0/)：

```text
data/public/v0.3.0/
├── studies/
│   └── PMID_<pmid>/
│       ├── endpoints.gff3.gz
│       ├── metadata.tsv
│       ├── metadata.json
│       └── [study-specific relation tables, when present]
├── release.json
└── SHA256SUMS.txt
```

当前共 13 个 PMID 目录。每个目录对应一篇论文，不管该论文登记了一份还是多份 `BATTER_S1` 来源。研究包包括：

| 文件 | 保存内容 | 读取说明 |
|---|---|---|
| `endpoints.gff3.gz` | 该 PMID 下各来源的 3′ 端位置记录。 | 每个 feature 保留 `source_id`，所以可以区分同一论文下的多份来源数据。坐标从 1 开始；每条记录只占一个碱基，GFF3 `score` 列为 `.`。 |
| `metadata.tsv` | 每个来源数据一行的可读摘要。 | 可直接用表格软件打开；字段为来源编号、物种、参考组装、PMID、论文标题、实验方法、记录数、证据类别、发布状态、许可、原始数据登录号和已知限制。 |
| `metadata.json` | 该研究各份来源数据的完整说明及发布信息。 | `sources` 数组保留每份来源的原值，包括字段映射、同一来源所有记录都相同的值、许可和证据判断。 |
| `gene_associations.tsv.gz` | 31594819 研究补充表中的 805 条基因与 3′ 端对应记录。 | 该文件放在 `studies/PMID_31594819/`；460 条关联公开端点，另 345 条未关联记录仍保留坐标，不计入端点总数。 |
| `condition_observations.tsv.gz` | 37402717 研究两种条件下的 2,277 条观察：`log` 1,333 条、`transition_stationary` 944 条。 | 该文件放在 `studies/PMID_37402717/`。同一端点可有多条观察；观察不增加端点记录数。 |
| `release.json` | 版本号、13 个研究包及其中各文件的清单、大小、SHA-256 和记录数。 | 位于版本目录根部；其中的 `path` 从该目录开始计算，在仓库和网站下载目录中都能直接找到对应文件。 |
| `SHA256SUMS.txt` | 发布文件的 SHA-256 校验值。 | 位于版本目录根部；不含自身校验值。 |

`metadata.tsv` 使用制表符分隔，每行代表一份来源数据，列顺序固定：

```text
source_id	species	assembly	pmid	title	assay	record_count	evidence_class	release_status	article_license	redistribution_status	raw_data_accessions	known_limitations
```

同一论文下若有多个来源，`metadata.tsv` 含多行，`metadata.json` 的 `sources` 数组也逐份保存完整信息。PMID 38030608 对应的目录保留 `BATTER_S1_002` 核查信息和零条记录，不把它并入其他研究。

## GFF3 坐标与来源字段

GFF3 坐标从 1 开始计数（1-based）；端点的起点和终点相同。关键列为 `seqid=reference_name`、`source=source_id`、`type=terminator_endpoint`、`start=end=biological_coordinate_1based`；链沿用原表值，phase 和 score 均为 `.`。固定端点编号在 `ID` 属性中，七个常用逐端点字段以独立属性保存。原论文中不适合直接映射到 GFF3 标准列的逐端点补充字段使用 `ann_<field>` 属性名，例如 `ann_locus`。属性按 GFF3 规则对 UTF-8 值进行百分号转义。

GFF3 中的七个逐端点字段和 `ann_` 属性，加上同一研究 `metadata.json` 中对应来源的 `table_defaults.endpoints`，可以还原原来的 24 列端点表。`annotation_field_map` 说明补充字段来自 GFF3 属性还是端点字段；同一来源所有记录都相同的注释值由 `annotation_defaults` 保存。校验程序会检查各表可否还原原始行。

GFF3 的一行表示**一份研究数据中的一条 3′ 端记录**，不代表全库去重后的位置。按 PMID 放在同一文件只改变交付方式，不会合并或去重来源记录。来源、样本、条件或链不同，即使坐标相同也不合并。基因对应记录中的 `link_status` 表示是否关联公开端点；未关联记录仍保留自己的坐标，不会因此增加端点记录数。

## 网站下载与兼容文件

网站下载页以 PMID 研究包为主入口，分别提供 `endpoints.gff3.gz`、`metadata.tsv` 和 `metadata.json`，并在有相关表时链接研究目录内的压缩 TSV。站点组装时另生成按来源拆分的 GFF3 和按参考组装拆分的 GFF3/metadata，供 JBrowse 轨道、来源页和基因组兼容下载使用；这些派生文件不替代规范的研究目录布局。

网站也可生成按组装打包的 ZIP 作为兼容下载。研究 GFF3 与元数据的规范路径是 `data/public/v0.3.0/studies/PMID_<pmid>/`；版本根目录只放 `studies/`、`release.json` 和 `SHA256SUMS.txt`。本版没有根级 `endpoints.gff3.gz`、`sources.json` 或关系 TSV，也不发布端点 CSV、TSV 或 BED。两份关系表只含各自研究的对应记录或条件观察，不是端点全集，不能替代 GFF3。

旧版完整字段模板保存在 v0.2.0 归档中。归档内出现的旧文件名（如 `endpoints.tsv`）是历史来源记录，不是 v0.3.0 下载文件。

## 增强数据的边界

原增强页面和专用网站/API 已移除。页面原来使用的六份数据文件按原字节保存在 [`data/registry/internal/augmentation/`](../../data/registry/internal/augmentation/)；附带说明记录了来源，并注明这些内容是预测结果，尚无实验确认。文件中缺少逐实例坐标，也就是每个预测对象的基因组坐标，因此本版不把 OTU 汇总数据写成 GFF3 位置记录，也不生成浏览器轨道。以后取得并核实逐条坐标，才能另做 GFF3。

## 读取 v0.2.0 历史文件

完整旧版文件保存在 [`data/archive/BTED-v0.2.0.tar.gz`](../../data/archive/BTED-v0.2.0.tar.gz)。归档文件的校验值见 [`BTED-v0.2.0.tar.gz.sha256`](../../data/archive/BTED-v0.2.0.tar.gz.sha256)，归档内每个文件的校验值见 [`BTED-v0.2.0.SHA256SUMS.txt`](../../data/archive/BTED-v0.2.0.SHA256SUMS.txt)。解压后仍是 `data/public/v0.2.0/` 路径。旧文件按原字节保留，但不代表当前网站的下载路径或运行状态。

在仓库根目录用 tar 解压到临时目录：

```bash
mkdir -p /tmp/bted-v02-archive
tar -xzf data/archive/BTED-v0.2.0.tar.gz -C /tmp/bted-v02-archive
```

PowerShell 可使用：

```powershell
tar -xzf data/archive/BTED-v0.2.0.tar.gz -C $env:TEMP
```

可在仓库根目录运行发布校验器。它会检查归档 SHA-256、旧版归档内路径与逐文件校验值，以及 v0.3.0 研究包和共享发布清单：

```bash
python3 scripts/validate_bted_v0_3.py
```

## 记录和证据

本版沿用此前选择来源和判断证据的规则。实验支持的 3′ 端不表示每个位点都经过单独的终止功能实验；纯预测结果和无法分开实验与预测的混合结果不进入公开端点文件。不同论文的原始分数分别保留，不能直接比较。具体依据见[来源说明](../SOURCES.md)。

## 校验与构建

在仓库根目录运行：

```bash
python3 scripts/validate_bted_v0_3.py
python3 scripts/validate_repo_layout.py
python3 scripts/check_markdown_links.py
```

发布校验会检查 study 元数据、GFF3 属性与来源默认值能否还原端点和补充信息，核对基因对应记录、条件观察、来源计数、端点 ID、坐标、特殊字符、未关联的基因记录、文件校验值，以及 v0.2.0 归档是否未变。Pages/Worker 组装、JBrowse 轨道和本地 API 的检查方法见[部署手册](../v0.3/deployment.md)。
